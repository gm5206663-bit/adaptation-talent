# Templates — blank forms for new holders

Three forms, one purpose: **keep every adaptation document in the house shape.** A new
holder, a new checkpoint, or a new milestone should never require inventing a format —
copy the form, fill the placeholders, cite the law.

| File | Fills | Standard |
|---|---|---|
| [holder-module.md](holder-module.md) | a new character- and universe-specific module | §71 (seven parts) |
| [status-panel.md](status-panel.md) | a full Definitive Status Panel | §69 (34 rows) |
| [adaptation-log-entry.md](adaptation-log-entry.md) | one adaptation-log milestone entry | §70 (eight parts) |

**How to use**

1. Copy the file next to where it belongs (`modules/<holder>.md`, the holder's
   `foundation/` or `bible/` folder, or the serial's logs).
2. Replace every `{{…}}`. Delete the guidance comments.
3. **Never invent law to fill a blank.** If a value isn't established, say so honestly —
   `{{unestablished}}`, `{{seed, state 4}}`, `{{awaiting author ruling}}` are all legal
   entries. The authority order (Master §1) outranks every form: the author's word first.
4. Labels are from the §22.1 state ladder (0–10), and every mastery claim states its
   **scope**. A blank that claims more than the story shows is a defect, not a shortcut.

module + 34-row panel), [modules/lan-shen-log.md](../modules/lan-shen-log.md) (log entries),
[modules/eternal-oc-mcu.md](../modules/eternal-oc-mcu.md) (a world with no cultivation at all).
